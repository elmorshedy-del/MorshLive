# V2 Reliability and Two-Account Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Apply Claude's approved October 17 handoff without disrupting existing playback.

**Architecture:** Keep the public Mist URL and existing account-A behavior. Introduce a backward-compatible multi-slot gate and controller, deterministic schedule, and independently released relay/player resilience. Default automation and second-account activation remain off until prerequisites and acceptance checks pass.

**Tech Stack:** Vanilla browser JavaScript, Cloudflare Worker, Node services, Vitest and node:test, Railway.

**Spec:** `docs/HANDOFF-V2-SECOND-ACCOUNT.md`, `docs/HANDOFF-V2-CHROME-FIX.md`, `docs/V2-CHROME-PLAYBACK-FINDINGS.md`.

## Global Constraints

- Public HLS shape remains `/hls/iptv-<digits>/index.m3u8`.
- Account credentials exist only in Railway variables; no credential URLs in logs, output, schedules or git.
- No IPTV Lab/Xtream changes, new dependencies, workflow edits, Mist configuration changes, or tree-wide rollback.
- Preserve current single-account behavior when `V2_IPTV_ACCOUNTS_JSON` is unset; `V2_AUTO_SCHEDULE` defaults off.
- Use the documented stream-change plan for gate and player changes; preserve every unrelated fingerprint.
- Relay recovery ships separately from two-slot control and Chrome changes. Measure one match window after relay deployment before Chrome release.
- Do not switch/off the active account or probe its provider media during viewer use.

## Review Focus

- Concurrent switches to the same channel must create only one provider pull (gateway regression test).
- Controller restart must derive ownership from Mist source hosts, including duplicate/unknown ownership (gateway regression tests).
- Malformed or stale schedule metadata must keep current inputs running (scheduler failure tests).
- A provider read rejected during retry or cancellation must release its one-pull lock (relay integration regression).
- Browser callbacks/timers from an old mount must not recover or destroy a replacement player (Chrome lifecycle behavior test).
